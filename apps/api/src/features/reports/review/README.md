# ReviewRewards runtime foundations

`createReviewRuntime({source,rewards,imageConfig})` returns a genuine DO `registry` plus `router`. Merge its commands/views and `imageBinding` with the existing registry; mount its router through `createApp`. Keys are `review:accept`, `review:reject`, `review:resolve`, `review:awards`, `review:image-context`, and the existing `contributor-dashboard`. No central API index is changed by this slice.

The required synchronous `SourceReviewPort` reads canonical reports/current knowledge/conflicts/evidence plus authoritative pairs, retrieves the persisted original submitter/captured epochs, reads normalized metadata, and applies canonical proposed report/knowledge/observation changes. Its apply must preserve other feature values and the actual simulator representation. The explicit synthetic adapter in `test/review/runtime` exercises real public Sources pure functions and real simulator transitions; it is not a production media/source fallback. Full Sources factory adoption remains a separate gate.

Call `createReviewSeed(initialCoverage)` in the scenario seed loader and store its result as `seed.values.reviewRewardsSeed`. Initial gaps carry opening sequence0. Accept combines public source acceptance, reward eligibility, report award pointer, audit, observations/knowledge, gap lifecycle, events and idempotent outcome in the single platform transaction. New contradictions publish canonical conflict occurrences. Conflict resolution threads one ledger through kept reports in deterministic order. No AI advice participates in this transaction.

`reconcileReviewGaps(context,currentCoverage,eventSequence)` must be composed inside the source/advance transaction after deriving the new clock/epoch/knowledge. It returns the own review store to place in the same transition values; emit the matching state event slot. This opens new gap occurrences after expiry/epoch changes while preserving prior points/history. The local Workerd clock fixture composes the hook; Lead must compose it in the genuine advance/source adapters.

`prepareImageReviewBinding` runs outside the transaction using crypto SHA256, then the source/media adapter persists its result with normalized metadata. Its digest binds session/generation/report, normalized hash, actual description/location/capture/vehicles/status, model/config/prompt/rubric. The synchronous imageBinding resolver only reads that persisted metadata and compares the current context. Unrelated operational revision is excluded.

`runImageReview` uses injected authorized normalized-image bytes and provider ports, verifies actual byte hash/context, calls the durable one-use start immediately before provider work, fully validates model-only output, derives the server rubric, and completes through the durable fence. Late human review/Reset/deadline never publishes local advice independently. `createResponsesImageReviewPort` uses native fetch, strict self-contained C1 schema, one image, no tools, bounded input/output, abort/deadline and no retries. Configuration/provider keys stay server-only. The implementation follows the official [vision input](https://developers.openai.com/api/docs/guides/images-vision?api-mode=responses) and [Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs?api-mode=responses) shapes; no live model call was performed.

Mount `createImageReviewRouter({media,provider,failQueued})` separately. GET returns nullable dispatcher-only state with no-store. POST stays503 when a genuine required port is absent, and never exposes leases or fabricates score0. The service direct success path is tested against real DO metadata and an explicit fake Responses transport, not a live provider.

Two platform seams are pending:

- Audit-only Reject needs atomic If-Match without increasing operational revision. Current platform couples CAS to `operational`. The real reject transition is implemented in `reviewReportTransition`, but its HTTP command deliberately returns503CONFIG_INCOMPLETE until an independently enforced metadata-CAS flag/hook is supplied. Do not pre-read CAS in HTTP or omit it.
- Queued storage failure needs a fenced terminal failure before start, without incrementing provider-call budget. Existing `complete` rejects an unstarted job. Inject a genuine `QueuedImageFailurePort` after SessionPlatform supplies it; image POST remains503CONFIG_INCOMPLETE until then. Never simulate a provider start or silently relabel storage failure as timeout.

Awards are dispatcher-only and paginate with a signed cursor bound to session/generation/revision/limit, using the existing server locator key with a dedicated purpose. Contributor dashboards select the authenticated bound entity, never a client selector. No source/router/provider operation changes actor capability. Full review-ready, production source/media, IR12 live vision, device and calibration gates remain pending.

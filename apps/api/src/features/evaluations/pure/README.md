# Pure ten-trial evaluation aggregation

`aggregateEvaluation` consumes exactly ten unique first-proposal trial IDs 1–10 at one explicit model configuration hash and returns canonical `EvaluationRun`. It sorts a copy; caller data is unchanged. Timeout, refusal, invalid output and other failed trials stay in the denominator. Contradictory valid-success records are rejected rather than repaired. A nonnull execution error requires failed=true, including invalid first proposals. Failed samples retain canonical nullable error codes and any blocked/rejected plan ID for audit. Inputs must be independent first responses collected by the eventual authorized runner; this aggregator cannot prove independence or execution provenance.

`nearestRankP95` uses `ceil(0.95*n)` on sorted finite nonnegative measured latencies. For ten samples it is the maximum. A measured failed response still contributes its latency. Any missing measurement yields null p95, never zero or a percentile from favorable samples. Finite latency does not turn a failed trial into a valid proposal. No K4 acceptance is inferred from a percentile; all trial outcomes remain visible.

`is_real_model` is retained from explicit provenance supplied by the caller, never inferred from schema/unit tests. `status: completed` means all ten records were aggregated, not all trials passed. This module performs no provider calls, retries, clock reads, durable jobs, budget spending or evidence fabrication. Real-model and full rehearsal acceptance require separate authorized execution.

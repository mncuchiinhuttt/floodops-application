# M1 v0.5 contract cutover

Canonical M1 source: the four JSON artifacts in this contracts directory. Run `bun packages/contracts/scripts/generate.ts` and `--check`; active surface is `packages/contracts/src/generated/contract-surface.json`. The historical root definition/contract-surface/README artifacts are outside this narrowed work item and remain preserved v0.3 snapshots; Lead must repoint the consumer index/docs to the new generated surface. They are not M1 inputs.

Before: 66 operations, 61 paths, 194 schemas, eight model tool registrations. After: same 66 operations/61 paths, 197 schemas, eight internal services (seven M1/one M2 deferral), zero model-callable operational tools. No campaign/student/forecast endpoint is added. Photo ModelOutput/Advice/Job/input shapes and image-quality-v1 remain unchanged; M1 visible_summary/reasons describe visible flooding/obstructions and inability to determine depth. Numeric depth/validated scale-reference is M2 and must not be fabricated.

New-session serialization version: m1-v1, contract 0.5.0-m1. Start new sessions/Reset through a coordinated version switch; never load old stored reports/jobs as new DTOs, auto-pin a missing receipt policy, retro-award, silently assign default points or migrate free-report points into campaigns. Keep legacy sessions/evidence isolated until expiry; no speculative data rewrite is included. All affected producers/clients must cut over together before Lead publishes a fresh contracts-ready/consumer receipt.

Report adds required reward, review_result_id and reviewed_at. reward has status pending_review/pending_config/ineligible/committed, immutable policy(policy_id/version/config_hash) or null, reason_code and nullable award_id. Missing configuration at receipt means policy=null/status=pending_config/reason POLICY_NOT_CONFIGURED/award_id=null, including after successful manual review. Knowledge/observation commit does not wait for rewards or AI. No fake zero-point award; existing points_total is committed ledger only. Policy amount and per-report/per-gap interpretation must come from explicit pinned config, never a default. First fill follows accepted transition order, not arrival-time fairness.

Committed Award adds reward_policy and review_result_id and retains positive points>=1. parseM1ReviewResult checks reward/report/award/review/policy identity; the HTTP client invokes it for reviewReport. assertReceiptRewardPolicyUnchanged rejects changes to a pinned policy, including null→later-config. Source must pin at receipt, Review must evaluate and write atomically against that immutable reference, Session must persist/replay the exact result; wire helpers do not grant rewards.

PlanningJob replaces model/model_config_hash with planner {kind:deterministic,algorithm_version,config_hash,search_limit}. search_limit counts candidate evaluations and is explicit, positive and safe-integer; no numeric default is imposed. Stable tie-break and budget enforcement belong to Planner. NO_FEASIBLE_PLAN requires failed/null plan/completion time and means bounded search found no valid candidate, not global infeasibility. PLANNER_TIMEOUT distinguishes a server deadline from photo MODEL_TIMEOUT; both terminal failures keep plan_id=null. Existing plan/action/group/CAS/approval/Execute DTOs are preserved. Evaluation kind model_quality becomes deterministic_replay; EvaluationTrial.model_config_hash becomes planner_config_hash; EvaluationRun.is_real_model remains false-only for compatibility. Driver text remains accepted for deterministic clarification/manual review, never model parsing or evidence authority.

Consumer rollout: Sources report receipt/serialization, Review result/award creation, Session persisted state and new-session version selection, Planner jobs/evaluation, Web report/reward feedback. Existing HTTP operation names, request auth/CSRF/Idempotency-Key/If-Match/Reset semantics and SSE controls remain. Do not mount the new wire onto old producers or claim M1/E2E pass from schema tests.

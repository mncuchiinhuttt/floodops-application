# Cloudflare Workers + Hono: platform research and recommendation

## Executive recommendation

Use one Hono Worker as the production API and static-asset origin for the web SPA. Bind one SQLite-backed Durable Object (DO) per simulator session, a private `REPORT_MEDIA` R2 bucket for normalized user reports, and a separate private `SCENARIO_ASSETS` R2 bucket for approved immutable fixture assets. Treat the DO as the only authority for session state, revisions, idempotency, event sequence, and wall-clock expiry. Keep domain reducers synchronous and portable; put no network call inside a SQLite transaction. Do not add D1, KV, or Queues for the stated MVP: the session DO is the consistency boundary, R2 owns blobs, and the API has no independently durable job requirement in the current PRD.

This is a proposed architecture, not an availability or latency guarantee. Cloudflare product plans, limits, and features must be rechecked against the chosen account before implementation.

## Session state, long model calls, and isolation

- Resolve `SESSIONS.idFromName(session_id)`; use a cryptographically random opaque session ID, not participant-controlled names. Each session DO owns that session's state and SQLite rows; there is no global mutable simulator object.
- Persist the authoritative snapshot, `revision`, independent `event_sequence`, idempotency records, report metadata, and schema version in SQLite. Use event sequence only as a replay cursor; it is not a substitute for operational revision.
- Snapshot+revision capture trước network; transaction recheck generation/revision/latest plan/job pointer. HTTP stale revision dùng `412 REVISION_MISMATCH`, same-revision superseded plan dùng `409 STALE_PROPOSAL`; không dùng error code tự đặt khác OpenAPI. Model failure không rollback committed report/execution.
- Keep the final commit synchronous and bounded. If a model call is slow, allow it to fail/timeout as a structured no-op; do not hold SQLite locks or a DO input gate around the remote call. Platform request duration is not asserted here; no unbounded-work promise is made.
- Reset cross-DO saga persist **old resetting lock và replacement ID trước await**. Initialize target idempotently, ghi sealed outcome, tombstone rồi private reply. Crash resume cùng target, old mutations luôn denied; không claim distributed atomicity. Narrow same-reset replay accepts original hoặc recorded replacement owner credential với key/digest/Origin/CSRF để phục hồi body loss sau cookie rotation.
- An initiating dispatcher receives a new capability only in the reset response. Other devices must rejoin using an explicit secure handoff/rejoin flow; do not broadcast a bearer capability on an unauthenticated event stream. A lost response must not silently restore old capability validity.

## Realtime transport

Expose separate cursor endpoints: `GET /api/v1/sessions/{session_id}/events?after={event_sequence}` returns bounded JSON catch-up; `GET /api/v1/sessions/{session_id}/events/stream` is bounded, read-only SSE with event IDs. SSE reconnects from `Last-Event-ID` (or a cursor query on first connect), has finite lifetime and heartbeat, and requires snapshot resync on cursor gap/reset. Normal authenticated JSON commands mutate state; WebSocket's bidirectional connection state is not required.

Use `fetch()` + `ReadableStream` consumption on web and Expo. Expo's official [`expo/fetch` API](https://docs.expo.dev/versions/latest/sdk/expo.md) documents streamed response-body consumption with `getReader()`, making native SSE eligible; still test abort, reconnect, auth headers, and app suspension on devices. Do not rely on native `EventSource`. If the selected runtime suspends or cannot maintain the stream, use JSON cursor catch-up polling as the concrete fallback. No transport choice is a delivery guarantee: clients must resync from a snapshot after cursor loss.

## Private image path and sanitization

Private REPORT_MEDIA/SCENARIO_ASSETS không có public domain. Exact routes: `POST /api/v1/sessions/{session_id}/media-uploads`; `PUT /api/v1/sessions/{session_id}/media-uploads/{upload_id}/content`; `POST /api/v1/sessions/{session_id}/media-uploads/{upload_id}/completion`; `GET /api/v1/sessions/{session_id}/media/{media_id}`. Server resolve session ownership trước read/body; no arbitrary key/URL. Approved fixture GET dùng `/sessions/{session_id}/fixture-assets/{asset_id}`. Enforce bytes/decoded bounds trong operational limits, JPEG/PNG + sanitizer, không magic-only safety.

A magic-byte/MIME check alone is not image sanitization. Preferred implementation is decode/re-encode using the Cloudflare Images binding and explicit metadata removal, then persist only normalized output to private `REPORT_MEDIA`; expose the binding in Wrangler config. Treat entitlement and a Worker-compatible transformation path as a release prerequisite. If unavailable, fail closed on arbitrary user image uploads rather than claim an in-Worker signature parser makes them safe. Store upload/media metadata in the session DO; use a server-generated object key. Do not expose public R2 URLs. Source: [Cloudflare Images transformations](https://developers.cloudflare.com/images/transformations/).

## EAS boundary

Cloudflare hosts the web SPA/API and server-side state/media only. iOS/Android binaries are built/signed/distributed by Expo Application Services (EAS), not Workers or R2. The native app calls `/api/v1`, persists only its participant capability in platform secure storage, and uses the same wire contracts/domain packages; app binaries and signing credentials never become Cloudflare static assets or Worker secrets.

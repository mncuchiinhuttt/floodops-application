# FloodOps web UI

The public root exports accessible controls (Button/IconButton/LinkButton, fields/image picker, badges, Card/MetricCard/Alert/Skeleton/Toast), Radix Dialog/Sheet/Tabs/Tooltip, Form/ErrorSummary, responsive DataTable/KeyValueList, and the shared presentation families below. React 19.3 and Radix pins come from the reviewed workspace; no generator or app config is needed. Load `@floodops/design-tokens/styles.css` followed by `@floodops/ui-web/styles.css`. Tailwind v4/Storybook integration is local to `.storybook`; consumers use their approved build setup.

- Context: SimulationBanner, CalibrationStatus (incomplete/failed/validated), SourceCard, EvidenceSummary, RuleId.
- Map: MapCanvas, MapLegend, MapEntityMarker, RouteSummary.
- Planning: PlanActionCard, PlanDiff, GateReasonList.
- Reporting/results: ReportForm, ReviewDecision, GapCoverage, PointsLedger, EventTimeline, ResultComparison.
- Explicit actions: ConfirmationControl and ResetControl.

Presentation types in `@floodops/design-tokens` are UI-only view models, not wire DTOs/schemas or copied business rules. A feature facade maps frozen `@floodops/contracts` responses into display labels/values and supplies capability-based callbacks. These components never fetch, read a clock, infer freshness/passability, award points, approve a route or execute a session mutation. Projected/committed labels remain explicit; null values say Unavailable and numeric zero remains zero. Points are always Simulated; event sequence is labelled separately from operational revision.

Button defaults to type=button. Disabled controls require a visible reason at compile time and runtime; IconButton preserves the same union. Plain text fragments supply a name; opaque rich content needs aria-label. Pending prevents activation and exposes busy/status text. Refs reach the actual control. Fields always have visible labels and linked hints/errors. ImagePickerField only forwards selected File[] and renders controlled id/label/count/removal; MIME accept is UX, not image validation. It does not upload, preview raw media or bypass server normalization.

Form prevents browser navigation. After failed submit, update errors and increment submissionKey; ErrorSummary focuses itself and links to field IDs. ReportForm accepts the same errors/key, validates an optional required caption, retains controlled draft values and waits for consumer callbacks. ReviewDecision exposes manual Accept/Reject callbacks with an optional required reason; no AI state can disable them implicitly.

Dialog/Sheet use Radix modal isolation, focus containment and Escape dismissal, with optional initial/return focus refs. ConfirmationControl starts on Cancel, invokes onConfirm only after explicit confirmation, blocks dismissal/duplicate confirmation while pending, rechecks current disabledReason, shows a safe failure message and restores focus after completion (or a readable fallback if capability disabled the trigger). Supply a deadline-bounded callback from the typed API facade; closing is not represented as cancellation of an in-flight mutation. ResetControl also explains new-session/rejoin semantics.

Tabs support roving keyboard focus and disabled tabs. Tooltip opens via focus, hover or explicit activation and dismisses with Escape. Every control targets 44px minimum; no nonessential animation is used. DataTable uses one semantic tree with stable header IDs, visually labelled card rows below 48rem and no duplicated interactive cells. Row keys must be stable. Error/loading/empty states are distinct.

Maps receive structured finite display points, explicit view-box/scale/vehicle labels and consumer-supplied states. Out-of-view geometry fails rather than being silently clamped. Road tokens supply line color/pattern; conflicting or closed state stays on an outer stroke when a proposed route is shown as a thin inner stroke with a contrast separator. A complete ordered segment/marker alternative remains available. Markers become buttons only with explicit callbacks. Route display never grants safety/approval.

Run `bun run --cwd packages/ui-web test`, package typecheck and `bun --bun run tsc -p packages/ui-web/test/tsconfig.json`. Axe component tests exclude color-contrast only in JSDOM; token pair tests and real-browser Storybook checks provide separate evidence. `bun run --cwd packages/ui-web build:storybook` compiles Tailwind and 17 state/interaction stories. `bun packages/ui-web/dev/serve-storybook.ts` serves that build only at 127.0.0.1:6006. Development galleries/stories are not production-root exports.

Token/prop breaking changes need approved receipt/version and coordinated web/native consumer migration; update canonical tokens plus both adapters, preserve notices and rerun behavior/contrast/render tests. Automated component evidence is not full application WCAG, device, security or release clearance. Native AT/manual integration remains phase 11/operator work; known Expo CLI Zod 3/deepmerge audit qualifications remain unchanged.

# FloodOps native UI

Public root exports native Button/IconButton/LinkButton, TextField/TextArea/SelectField, StatusBadge/ProvenanceBadge/PriorityBadge, Card/Alert/Skeleton, Dialog/Sheet, Tabs, Tooltip, Form/ErrorSummary, AccessibleList/KeyValueList plus public prop types. React 19.3/RN 0.88.1/SVG 15.16 and Expo 58 test tooling are in the reviewed frozen baseline. No DOM/ARIA/Radix/web imports or app imports. ExpoMobile owns the safe-area screen adapter and will import FoundationsGallery from a Lead-published `/gallery` subpath.

Controls use platform labels/roles/states,48dp minimum targets, scalable text and visible keyboard focus. Disabled requires a visible reason, pending prevents activation, rich status has visible text plus a decorative vector. Refs reach the native Pressable. Fields preserve consumer state and include error text in hints. The app owns final validation/announcements and server authority.

Dialog/Sheet use native Modal, labelled heading/description, explicit close and Android request-close callback. Content scrolls rather than clipping enlarged text. On show, accessibility focus targets the title; pass returnFocusRef to restore the originating control on close. This is framework code with native bridge behavior still requiring device verification. SelectField supplies that ref, shows labelled radio choices in a sheet, disables unavailable choices with reasons, and calls onValueChange only after an explicit enabled choice.

Tabs expose platform tab role/selected state and show only selected content. Tooltip opens on press/focus, stays open on focused activation and has explicit dismissal rather than hover-only UI. Form/ErrorSummary displays consumer errors; increment submissionKey after failed submit to request accessibility focus. Error items may provide a focus callback to the actual input. It never validates a session or executes a domain action. AccessibleList renders each column label/value without a clipped horizontal table, with distinct loading/error/empty states. Cell render functions must be pure; stable row keys required.

Status/provenance/priority stay separate. Reference data, Replayed and Simulated are visible; accepted/rejected/zero points/offline/stale are explicit caller labels, never inferred safety/reward state. Alert accepts semantic tone and explicit urgency. No nonessential animation or network activity.

Typechecks pass on the reviewed baseline. Actual native Jest render/interaction suites currently fail before test execution because Babel transforms icons/src/native but @babel/runtime 7.29.7 is only declared by ui-native. Lead must declare that dependency in icons; no sibling/private dependency workaround is used. Run `bun run --cwd packages/ui-native test --watchman=false` after the baseline fix. Test files exercise real native components through mocked platform bridges; that cannot establish iOS/Android SVG, VoiceOver/TalkBack, safe-area, enlarged-text or switch/keyboard results on devices. Those remain pending; no native/UI/release gate is claimed. Breaking props require approved consumer migration; do not copy shared primitives into apps.

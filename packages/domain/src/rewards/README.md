# Reward domain proposals

`@floodops/domain/rewards` exposes pure coverage, active-gap projection and gap/reward ledger proposals. Inputs are canonical validated DTOs plus explicit server-owned current epoch, simulation time, session/generation, event sequence, IDs, normalized media identity and award configuration. None of these functions authorizes a caller, accepts a report, changes knowledge or commits a transaction.

`deriveUsefulCoverage` checks the current segment/vehicle/epoch independently. A shared observation's aggregate `has_conflict` flag is not a per-vehicle decision. Coverage uses accepted available-source observations with `observed <= now < expires`, requires known nonunknown current knowledge, rejects any matching contrary condition even if its ID was omitted from the projection, and returns only linked supporting IDs. Low confidence can count coverage; it grants no route permission. Full profile/location/timestamp/closure normalization remains with the SourcesMedia public seam.

`projectActiveGaps(ledger, currentScope)` returns an isolated frozen array of open rows matching exact current relevant segment/vehicle/epoch tuples, preserving ledger order. Use it for current displays/counts. Keep `ledger.gaps` as complete audit history: a prior-epoch open row stays open in history, does not become filled by an epoch change, and is excluded from current eligibility. Existing fill proposals also require an exact current tuple. The caller supplies authoritative scope; the projection infers no epoch or clock.

`proposeGapOpenings` allocates explicit unused occurrence IDs. `proposeSourceGapFills` permits non-report source recovery without an award. `proposeReportReward` accepts already-normalized accepted report evidence, blocks unresolved/contrary current evidence across every vehicle the report covers (including explicit scopes whose knowledge row was omitted), and preserves hash claims for later resolution. A conflict restricted to a different vehicle cannot veto a car-only report. The server must configure positive points and eligible community-source IDs; there is no default award value.

A report can receive at most one award; a gap at most one first-fill award. Normalized photo identity is unique across reports/contributors within the ledger. Expiry can open a fresh occurrence without clawback, and Reset seeds a separate empty generation. Outputs clone/freeze state, retaining prior audit rows and awards. These checks support a candidate only: the durable owner must atomically commit accepted knowledge, gaps, awards, idempotency and events in the genuine runtime integration.

Image-quality rubric derivation is isolated under `apps/api/src/features/reports/review/rubric/`; no AI output is an input to these reward functions. This partial domain does not implement the review router, media/job/provider service, actor authorization or durable race/crash behavior.
